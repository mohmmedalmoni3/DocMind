# دليل التشغيل المطلوب من Codex توثيقه والتحقق منه

هذا دليل متوقع للمشروع الذي سيبنيه Codex، وليس دليلًا لتشغيل هذه الحزمة وحدها؛ الحزمة لا تحتوي main.py منفذًا.

## قبل المسابقة / قبل قطع الإنترنت
1. تثبيت Python المناسب للمشروع وOllama.
2. الحصول على الاسم الدقيق للموديل من المنظمين.
3. تنزيله أثناء توفر الإنترنت، باستبدال PLACEHOLDER بالاسم الصحيح:
   ollama pull PLACEHOLDER
4. إنشاء بيئة داخل مجلد المشروع:
   python -m venv .venv
5. تثبيت مكتبات المشروع:
   .venv\Scripts\python.exe -m pip install -r requirements.txt
6. وضع ملفات الخدمات الرسمية في data/، وملفات التدريب في مواضعها الصحيحة.
7. ضبط المتغير في PowerShell بالاسم الحقيقي:
   $env:OLLAMA_MODEL = "PLACEHOLDER"
8. تشغيل فحص الجاهزية الذي ينفذه Codex، وفحص قائمة الموديلات المحلية عبر ollama list.

إذا كانت ollama غير معروفة في PowerShell، تحقق من تثبيتها وPATH، ثم افتح نافذة جديدة. لا تخلط بين تثبيت حزمة Python وبين تثبيت تطبيق Ollama والموديل.

## تجربة التدريب
تشغيل Ollama محليًا؛ إذا لم يكن الخادم يعمل استخدم ollama serve وفق بيئة جهازك، ولا تشغل نسخة ثانية على نفس المنفذ.
من مجلد المشروع:
.venv\Scripts\python.exe main.py questions.json

الناتج answers.json بجانب main.py. راجع صحة البنية وقارن المعنى مع answers_example.json الرسمي. الأمثلة في examples/ بهذه الحزمة مخصصة لشكل البيانات فقط.

## يوم التقييم
أبلغ اللجنة إذا كان التنفيذ يحتاج أمر البيئة الافتراضية بدل python العادي. نزّل كل شيء مسبقًا، اختبر مع الإنترنت مطفأ مع بقاء localhost متاحًا، ثم اللجنة تضع أسئلتها المخفية وتشغل الأمر. لا تعتمد على الواجهة. احتفظ بنسخة أصلية من الملفات ولا تعتمد على أسئلة محفوظة.

## ماذا تعرض للجنة؟
- كيف ميزتم الخدمات المتشابهة والحالات الأربع.
- كيف حافظتم على شروط الرسوم والملاحظات.
- كيف خرجت contexts من النص الفعلي.
- كيف يتعامل المساعد مع الغموض والسؤال خارج نطاقه.
- القياسات الحقيقية على جهازكم والقيود المتبقية.
