# حزمة تسليم المسابقة — تدقيق التوافق

المصدر الملزم: challenge_brief.pdf المقدم من المستخدم، 7 صفحات، وبالأخص قواعد الصفحة 7. هذه حزمة مستقلة عن واجهة العرض. مجلد `data/` يضم نسخ الملفات الاثني عشر الأصلية؛ لا يحتوي مواد أطلس أو الدورة أو إجابات المثال. Python يستخدم المكتبة القياسية فقط. لا يلزم Next.js أو npm لهذا المسار.

## فرق حاسم عن واجهة DocMind

القواعد تقول إن كل إجابة يولدها نموذج اللجنة أثناء التشغيل، وتمنع الإجابات الجاهزة. واجهة DocMind تحتوي اقتباسًا مباشرًا وإعادة تشغيل أجوبة مخزنة؛ لذلك **لا تستخدم واجهة العرض أو مسارها القديم كتسليم اللجنة**. مسار main.py الجديد يستدعي نفس النموذج المحدد للتخطيط ولصياغة كل جواب، بما فيه التوضيح والامتناع. لا توجد إجابات ثابتة للأسئلة الرسمية. القيمة `error` تستخدم فقط عند فشل المعالجة كما يجيز ملف القواعد.

## التشغيل

من هذا المجلد، بعد تجهيز Ollama والنموذج محليًا:

```powershell
$env:COMPETITION_MODEL='command-r7b-arabic:7b'
python main.py questions.json
python verify_submission.py questions.json answers.json
```

Linux: `COMPETITION_MODEL='command-r7b-arabic:7b' python main.py questions.json`.

حدد المستخدم نموذج اللجنة command-r7b-arabic:7b. يستخدمه البرنامج افتراضيًا ويرفض أي اسم مختلف؛ لا يوجد نموذج احتياطي. `answers.json` يكتب بجوار main.py بصيغة UTF-8، مع حفظ ذري بعد كل رسالة. `run-report.json` يسجل أزمنة الرسائل وعدد نداءات النموذج وبصمات الملفات دون نصوص الأسئلة.

## تدفق المعالجة

ملفات أصلية → حذف قوائم الموقع قبل أول حقل → مقاطع الحقول التسعة كاملة → نموذج اللجنة يحدد الخدمات والحقول لكل أجزاء السؤال → ضم الشروط والملاحظات، والوثائق عند طلب الرسوم → نموذج اللجنة يولد جوابًا وIDs للأدلة → تحقق بنيوي من IDs → إرجاع النصوص الأصلية لهذه الأدلة فقط → حفظ JSON.

الملفات قصيرة ومتشابهة جدًا؛ اختير استرجاع بنيوي بالخدمة والحقل لهذا المسار بدل إضافة نماذج أخرى قبل قياس فائدتها. هذا لا يعني أن Hybrid RAG سيئ أو أن التخطيط بالنموذج مضمون: يجب قياس أخطاء اختيار الخدمة والحقول على مجموعة مستقلة. أرقام الخدمات والحقول ليست أجوبة ولا حقائق معدلة. لا تنقل خطأ إملائيًا إلى حقيقة جديدة ولا تختصر الاستثناءات من المصدر.

## مصفوفة التوافق

| الشرط | الحالة الحالية |
|---|---|
| python main.py questions.json | مدخل موجود؛ اختبار التشغيل الفعلي بالنموذج مطلوب |
| answers.json بنفس الترتيب والمعرفات والسؤال | اختبارات عقد الإدخال/الإخراج ناجحة |
| answer + contexts لكل رسالة | حفظ تدريجي، وerror للسؤال المتعثر |
| 12 ملفًا فقط كمصدر | قارئ محصور بأسماء الملفات المعروفة |
| كل جواب يولده النموذج المحدد | مصمم بهذا الشرط؛ لا cache أجوبة ولا نقل مباشر |
| لا تبديل نموذج اللجنة | مقفل على command-r7b-arabic:7b وفق تحديد المستخدم |
| contexts مقاطع مستعملة لا ملفات كاملة | مقاطع بنيوية يختار النموذج IDs منها؛ تحقق تطابق النص |
| متابعة داخل المحادثة وعزل بين المحادثات | اختبارات آلية ناجحة؛ صحة الإحالة الفعلية تحتاج اختبار النموذج |
| رسوم الحالات والملاحظات والأسئلة المركبة | حفظ الأدلة ذات الصلة؛ صحة الاستنتاج لم تُثبت بعد |
| تشغيل بلا إنترنت | اعتماد على loopback ومكتبة قياسية؛ لم يتم فصل Wi-Fi فعليًا |

## مراجعة الأسئلة التدريبية الستة

`answers_example.json` مرجع تقييم فقط، لا يقرأه البرنامج. بعد تشغيل النموذج راجع:

1. تجديد دفتر العائلة: 45 دقيقة، لا مدة خدمة أخرى.
2. جواز بدل فاقد: المكاتب والسفارات والقنصليات، دون خلط شروط بدل تالف.
3. وثائق تجديد الدفتر: العناصر الثلاثة مع شرط «لمن يلزم».
4. متابعة السفارة: يبقى موضوعها تجديد دفتر العائلة من الرسالة السابقة.
5. المقارنة: صورة واحدة للبطاقة لأول مرة وصورتان لتجديد الجواز؛ دليل مستقل لكل خدمة.
6. أسعار الطيران: امتناع وcontexts فارغة.

هذه توقعات من ملف المثال، ليست نتائج تشغيل. لم يُنشأ ملف answers.json مزيف ولم تُحسب دقة من إجابات المرجع. أداة verify_submission لا تقيس صحة المعنى؛ المقاطع الصحيحة لا تثبت استنتاجًا صحيحًا.

## معايير الإفراج عن النسخة

- تشغيل الأسئلة الرسمية التدريبية على نموذج اللجنة نفسه؛ فحص صحة الستة يدويًا وربط كل معلومة بسياقها.
- إضافة حالات غير موجودة في المثال: أول/متكرر فقدان، داخل/خارج الأردن، العمر، صلاحية الجواز، رسوم المستعجل، موافقة الزوج، القاصر، الأب والأم المتوفيان، الغموض والأسئلة متعددة الأشخاص.
- فصل دقة اختيار الخدمة عن اكتمال الأدلة ودقة الإجابة والإسناد. قياس زمن التخطيط والتوليد منفصلين، ثم p50/p95 مع عينة كافية. لا تعتبر ستة أسئلة قياسًا عامًا.
- مراجعة هجوم تعليمات داخل الوثائق، الأرقام المكتوبة بالكلمات، وتجاوز طول السياق. الحماية الحالية تحقق IDs ومصدر النص، ولا تثبت استلزام كل جملة أو تمنع جميع حقن التعليمات.
- تأكيد num_ctx=16384 على الجهاز. حد أحرف الأدلة محافظ ولكنه ليس tokenizer حقيقيًا؛ يلزم فحص prompt_eval_count/اقتطاع النموذج قبل اعتماد المقارنات الطويلة.
- تشغيل مع الإنترنت مفصولًا، ثم إخراج JSON نهائي بلا errors. لا رفع ملفات اللجنة تلقائيًا إلى مستودع عام.

## نتيجة التدقيق الحالية

جرى فحص القواعد نصيًا وبصريًا، وتم استخراج 108 حقول من 12 ملفًا. نجحت اختبارات Python المحلية الخمسة لعقد التسليم، وعزل الأخطاء والمحادثات، وسلامة المقطع وإلزام المرور بالنموذج (باستخدام نموذج وهمي في الاختبار). تم تشغيل الأسئلة الستة على command-r7b-arabic:7b وإصلاح إخفاقات اختيار الأدلة والمتابعة. التفاصيل والحدود في RUN-RESULTS-AR.md. لا تُعد العينة اختبارًا خفيًا أو إثبات دقة عامة.

تمت استعادة إمكانية التنفيذ وإكمال الاختبار الحقيقي. نتائج الامتناع أعيد توليدها بعد منع الشرح العام خارج الوثائق. لم يتم اختبار فصل Wi-Fi فعليًا.
